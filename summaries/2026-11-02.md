1. **Anthropic 全面加码网络安全防御，推出 Cyber Mission 与 OSS Scanner**：Anthropic 正式启动网络安全长期计划，包括为关键基础设施提供商部署 Claude 模型和驻场工程师的 Critical Infrastructure Defense Program，以及为开源项目提供免费自动化漏洞扫描的 OSS Scanner。这标志着 AI 安全能力从"发现漏洞"转向"规模化防御"，且 Anthropic 明确预测"两年内 AI 将有利于防御方"。

2. **AI 数学能力突破引发方法论反思**：OpenAI 模型接连解决 Erdős 单位距离猜想、Navier-Stokes 方程等百年难题，Latent Space 的深度分析指出关键差异——LLM 采用"深度优先+自动验证"的搜索模式，与人类"广度优先+高门槛筛选"截然不同。这意味着"提示质量"的门槛被大幅降低，计算可以替代时间，可能重塑数学研究的组织方式。

3. **"Black October"暴露 AI 加速的网络安全危机**：Latent Space 报道的集中漏洞披露事件包括 PHP 未授权 RCE、GitLab CVSS 10 分漏洞、LiteLLM 供应链攻击等，月度 CVE 数量从 4 千激增至 1.5 万。更值得关注的是，微软归因的 Storm-0940 国家行为者已使用开源 agentic 渗透框架 ARTEX，在部分案例中 3 小时内获得特权访问。

5. **Hugging Face 生态全面拥抱原生 TPU 支持**：TorchTPU 作为原生 PyTorch 后端推出后，Transformers、Diffusers 和 Kernels 均可直接通过 `device_map="tpu"` 或 `.to("tpu")` 运行，无需再依赖 torch_xla 或 Optimum TPU。这降低了 Google Cloud TPU 的使用门槛，且在批量推理场景下可实现 12-21 倍的解码加速。

**Hugging Face ❤️ TorchTPU: TPUs, Natively**

**核心论点**：TorchTPU 作为原生 PyTorch 后端推出后，Hugging Face 生态（Transformers、Diffusers、Kernels）全面支持 TPU，无需 torch_xla 或 Optimum TPU。

**关键要点**：
- 安装：`pip install torch-tpu --extra-index-url https://download.pytorch.org/whl/cpu`（避免拉取 CUDA 版本）
- Transformers v5：`device_map="tpu"` 直接加载模型；Diffusers：`pipe.to("tpu")` 或 `pipe.transformer.compile(backend="tpu")`
- TensorParallelConfig 支持模型自动分片到多芯片，无需单芯片容纳完整模型
- Kernels Hub 提供 Pallas 编写的 TPU 优化 kernel，批量 64 时 Qwen3-30B-A3B 解码加速 21.5 倍，Gemma 4 26B-A4B 加速 12.8 倍
- TPU 测试通过率 96.5%，已报告 34 个 issue 其中 19 个已修复，同时发现 Transformers 本身的 StaticCache 和 Qwen3 tensor-parallel 计划 bug

**值不值得深读**：强烈推荐，是 TPU 进入 PyTorch 主流生态的标志性文档，含具体性能数据和即用代码。

https://huggingface.co/blog/hf-torchtpu

**AI Is Getting Good at Math. Here's Why.**

**核心论点**：AI 模型突然在数学上取得突破（OpenAI 解决多个百年难题），关键不在于"更聪明"，而在于搜索模式的根本差异——LLM 的"深度优先+自动验证" vs 人类的"广度优先+高门槛筛选"。

**关键要点**：
- 问题复杂度可建模为"最短提示序列长度 k"与"执行工作量 t"的函数：2^k + t
- 人类约束：开发一个想法可能需要数月，因此需要早期证据才愿投入；AI 约束：验证一个完成的想法只需几分钟，因此提示质量门槛大幅降低
- LLM 的"贪婪深度优先"搜索 + 自动验证器 = 可以理性地投入巨大计算于不确定想法
- 每次失败尝试都成为"负面提示"反馈给下一轮，系统累积"什么已失败及为何失败"的指令
- OpenAI 的 CDC 证明提示示例：明确禁止"因当前方法失败就返回"等 learned laziness 行为
- 关键反直觉：Jacob Tsimerman（现 OpenAI 研究员）曾考虑单位距离猜想的反例方向，但停止了——不是缺乏技能，而是人类的时间成本使这个方向显得不值得深入

**值不值得深读**：强烈推荐深读，是目前对 AI 数学能力突破最有深度的方法论分析。

- **GPU 需求非矩形**：真实工作负载波动增长、峰值、下降，固定容量合同导致要么峰值时资源不足、要么平时闲置付费
- **Modal 的解法**：跨数千客户需求池化，将弹性需求转化为平滑聚合需求，实现"时长转换"
- **Sandbox 意外成功**：最初因 LLM 生成代码需要运行环境而推出，早期采用 modest 到差点关闭；后因 coding agent、background agent、强化学习需求爆发，现约占收入三分之一
- **快速启动是基础设施特性**：可用 GPU 缓冲池、自定义文件系统、进程检查点、GPU 内存快照，共同降低模型副本上线延迟
- **GPU 价格风险**：锁定当前价格后若 GPU 价格下跌，可能持有昂贵供给；Erik 认为不会立即崩溃但需纳入业务构建考量
- **工程文化**：Modal 代码审查是可选的（optional code reviews）

#### Argmin Gravitas (Ben Recht)

**Unimaginative Uncertainty**

**核心论点**：对"不确定性量化"狭隘方法的批评——过度依赖高斯假设的预测区间，忽视了更丰富的表达形式；真正需要的是"如果我们的故事错了该怎么办"的前事实分析。

**关键要点**：
- 当前标准做法：假设数据高斯分布，估计方差，设 ±2σ 边界；或从蒙特卡洛模拟/历史误差分位数构建
- 根本问题："概率"含义在这些模型中极其模糊，依赖不可验证的建模决策链，且无法二次量化模型本身的不确定性
- 政策分析中的实际用途：预测区间让预测者"不会错"，但 unclear 如何改变政策决策
- 更丰富的需求：人们想要"故事错了怎么办"的预案、如何从失败中恢复、不确定性的整体报告以帮助准备

**值不值得深读**：值得深读，对从事预测建模、风险评估的读者有哲学层面的启发。

https://www.argmin.net/p/unimaginative-uncertainty

**Too Big to Fail**

**核心论点**：通过凯恩斯宏观经济预测的历史，揭示"预测作为控制工具"的根本困境——Lucas 批判指出政策改变会改变模型参数，而参数改变不可预测。

**关键要点**：
- 凯恩斯将经济视为巨大控制问题：政府通过投资、税收、货币供应、利率等政策工具驱动经济产出和就业目标
- 预测需求由此产生：需要知道当前状态，更需要预测"无政策变化时"的未来状态
- **Lucas 批判（1976）**：模型参数拟合历史数据，不同政策产生不同参数，政策改变后参数变化不可预测——那么预测基础何在？
- 2003 年 Lucas 宣称"宏观经济学已成功解决萧条预防"，2008 年金融危机即为反讽
- 核心结论：宏观经济预测者的角色是"专家社区的审慎判断"，而非精确的量化计算；期望更多是不现实的

**值不值得深读**：推荐深读，对理解预测在复杂系统中的局限性有深刻历史视角。

https://www.argmin.net/p/too-big-to-fail

#### Latent Space (YouTube 播客)

**Using Agents for Long-Horizon Financial Work — Aman Singh, Arca**

**核心观点**：AI 原生财富管理公司 Arca 的 AI 平台负责人 Aman Singh 揭示，其 agent 系统的核心设计是"agent 比人更频繁地提示人"——主动、持续运行的服务，而非被动等待指令。

**主讲人**：Aman Singh，Arca AI 平台团队负责人；Arca 是近期融资 6,400 万美元的 AI 原生财富管理公司。

**关键洞见**：
- **AI 不替代顾问，替代顾问周围的所有工作**：客户不直接与 AI 交互，体验是通过人类顾问传递的"以前行业不可能的服务水平"
- **模型选择完全由内部基准驱动**：尽管外部基准吹捧 Luna，但实际太慢太贵；核心原则是 model-agnostic，自研 harness 抽象不同模型
- **任务分层**：税务分析等复杂任务用"最重 tier"模型（Opus 级或重 GPT），后台活动用低 tier 模型，金融顾问完全无感知
- **10 天级长周期任务的关键**：内部 memory 系统持续追踪"客户当前发生什么、谁负责什么、已发生什么、下一步什么、长期追踪什么"；每日"反思"进程更新世界状态
- **安全设计原则**：所有安全限制完全确定性，将决策权从 agent 手中移除；工具调用写入数据时运行 fast LLM 验证；边缘检测 prompt injection；数据外发时用小模型共识检查数据外泄
- **审计即默认**：每个 agent 动作产生变更日志（什么变了、谁变的、系统哪部分、何时），同样适用于人类操作——既满足合规，又为 agent 循环提供信息

**最有力引用**："Agents prompt people more than people prompt agents — and it is a proactive kind of service that is running for them twenty-four seven."
