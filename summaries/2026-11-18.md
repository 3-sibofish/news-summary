### 今日要点

1. **Anthropic 发布 Claude Fable 5.2 和 Mythos 5.2，模型能力跃升至解决开放科学问题**。Fable 5.2 在 prerelease 测试中完成了两项黑洞物理学开放问题的求解、30 小时内形式化证明了费马大定理、从零设计了三个可工作的电子设备，并协调超过 1,000 个子 agent 在八天内构建了一个可启动的原型操作系统。这标志着 frontier model 从"辅助编程"向"自主完成开放式技术探索"的关键跨越，且 Anthropic 首次将网络安全和生物安全能力拆分为 Mythos（需申请）和 Fable（全用户可用）两条产品线。

3. **Google DeepMind 发布 Gemini 4 Carbon 和 AlphaProof Code，在形式化验证和机器人领域实现双重突破**。Carbon 在网络安全基准上领先，更重要的是 AlphaProof Code 首次用 AI agent 在四周内完成了 Signal 加密协议核心代码的形式化验证——这是历史上首次对广泛部署的加密协议实现进行形式化证明，传统上需要专家团队数年。同时 Gemini Robotics 2.5 在 Mercedes-Benz 产线上实现 96% 成功率的自主 kitting 作业，显示 VLA 模型正从实验室走向工业场景。

4. **Devin Bots 和 Cursor Multiplayer 标志着"多 agent 协作"从个人工具转向团队基础设施**。Cognition 的 Devin Bots 将 agent 从"任务执行者"重新定义为"拥有持久身份和记忆的结果负责人"——Android Bot 在 44 天内自主合并 1,134 个 PR、编写 34 万行 Kotlin 代码，人类工程师仅发送 183 条消息。Cursor 的 Projects multiplayer 则让团队共享 agent 上下文和任务板，实现 agent-to-agent 的实时协调。两者共同指向：AI 编程工具的竞争焦点正从"单 agent 能力"转向"多 agent 团队编排"。

5. **Anthropic 开源 FlashProve 系统，推动"可证明推理"成为 AI 信任基础设施**。FlashProve 为 400B 参数的 Llama 4 Maverick 生成 zkSNARK 证明，速度达 110 tokens/second（H100），证明大小约 19MB，GPU 开销仅为模型本身运行的 70-95 倍——相比此前开源系统提升数个数量级。配合 Lean 形式化验证的顶层安全保证，这为模型提供商向用户、监管者和独立评估者证明"我确实运行了声称的模型"提供了密码学基础，对 AI  pacing 和合规具有深远意义。

#### Anthropic Research

- 发布五项开源成果：博客、技术报告、Claude 撰写的协议规范、可执行代码（C++ 快速验证器和 Lean 可证明正确验证器）、Lean 证明及交互式可视化工具
- 应用场景：独立评估者验证、第三方路由服务诚信保证、网络攻击检测、AI pacing 合规工具包

**值不值得深读**：值得。这是密码学证明与 AI 推理交叉领域的重要技术进展，对关心模型供应链安全和监管技术的读者尤为关键。

**Hugging Face 中的决策模型（Decision Models）**

**核心论点**：Hugging Face 引入"决策模型"新范式，让模型直接评估预定义选项并返回概率分布，而非通过文本生成间接推断，解决 LLM 在结构化决策中的模式保证、计算开销和架构不匹配问题。

**关键要点**：
- 决策模型接口：State + Questions + Allowed Answers → Decisions + Probabilities
- 支持多种问题类型：choice（选择）、score（评分）、noul（概率估计）
- 相比 LLM 生成 JSON：保证 schema 合规、消除约束解码开销、避免为简单决策进行完整自回归生成
- 相比传统分类：运行时动态定义标签，无需修改模型头部或重新训练
- 相比零样本分类：统一接口支持多问题、多类型、概率分布输出

**值不值得深读**：值得。这是 LLM 应用架构演进的重要概念，对需要高可靠性结构化输出的工程团队有实际指导意义。

原文链接：https://huggingface.co/blog/decision

**Palette：教小模型用您的设计语言构建演示文稿**

**核心论点**：IBM Research 与 Hugging Face 合作展示，通过合成数据训练和检查-修复 harness，20B 参数开源模型可在特定设计语言下生成与 frontier 系统竞争的演示文稿，同时保持数据所有权。

**关键要点**：
- 小模型生成演示文稿的三大难点：无法所见即所得的布局计算、同时处理编辑判断和几何放置、缺乏设计决策的训练数据
- Palette 将工作拆分为"设计师"（写 JSON 简报）和"编码器"（写 pptxgenjs 代码）两个角色，用单一 LoRA 适配器实现
- 合成数据生成：用大型开源教师模型生成约 1,000 份演示文稿、10,000 张幻灯片，包含反事实推理（"考虑过表格但选择图表，因为重点是趋势"）
- 检查-修复 harness：渲染后检测重叠和溢出，编辑模型重写问题幻灯片，仅保留确认改进的修复
- 用户可通过 [[指令]] 直接控制设计选择，如 [[make this a timeline]]

**值不值得深读**：值得了解。这是领域特定小模型训练和合成数据生成的精细案例。

#### The Pragmatic Engineer

**软件工程师的推理工程**

**核心论点**：随着 Uber、Pinterest、AT&T 等公司通过转向开源模型大幅降低 AI 支出，推理工程（inference engineering）正成为软件工程师需要熟悉的关键实践领域，文章通过与 Modal、Fireworks AI、Baseten 的深度访谈系统介绍该领域。

**关键要点**：
- 推理提供商与 AI lab 的区别：不预训练基础模型，专注开源模型托管、效率优化和定制服务
- 切换动机：成本（Uber 降 50%、Pinterest 降 90%）、延迟控制、微调需求
- 两阶段上云：第一阶段 API 替换（多租户），第二阶段专用 GPU 节点（需考虑模型大小、交互性 vs 吞吐量、KV cache、故障转移等）
- 前沿 lab 正常运行时间不足：Anthropic 99.5%、OpenAI API 99.97%/ChatGPT 99.2%，低于云服务商 99.99%+ 标准
- 推测解码（speculative decoding）：利用 decode 阶段未用计算，通过 Speculator 进一步提升推理性能

**值不值得深读**：值得。这是目前最系统的推理工程入门指南，对考虑从 API 转向开源模型部署的工程团队非常实用。

原文链接：https://newsletter.pragmaticengineer.com/p/inference-engineering-for-software-engineers
